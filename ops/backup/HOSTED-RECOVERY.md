## Что переносится

`recovery-source.cjs` проверяет SHA256 известного архива, штатно восстанавливает его только в случайную localhost-базу и удаляет временную базу/файлы в finally. Закрытый ключ и защитная фраза используются GPG через пути, без вывода содержимого. Служебный журнал PostgreSQL не пишет SQL ошибочных запросов.

`hosted-restore.cjs` собирает собственные public DDL/data/ACL, пользователей и identities Auth, а также собственный профильный Auth-триггер. Системные Auth/Storage DDL, функции, ограничения и платформенные default privileges сохраняются. Не импортируются их migration ledgers, OAuth-клиенты/секреты, сессии, refresh/one-time tokens, старые запросы привязки, lease/история runtime и очередь уведомлений. Поля одноразовых кодов пользователей очищаются; password hashes, подтверждение адреса, ограничения аккаунта и постоянные связи сохраняются. Активные MFA/WebAuthn/SSO требуют отдельного плана и останавливают этот исполнитель.

`execute-recovery.cjs` требует успешного native proof для того же SHA256 SQL-плана и свежего совпадения managed-структуры. Транзакция берёт advisory lock, проверяет пустоту цели, импортирует данные, проверяет counts/контрольные суммы/Auth/RLS до COMMIT и только затем фиксируется. Повтор поверх занятой цели запрещён. Неопределённый исход записи автоматически не повторяется: сначала нужно прочитать цель. После COMMIT выполняется ещё одна независимая проверка сохранённых данных и managed-структуры.

В копии выключены подписки Telegram; права запуска ingestion/scheduler отозваны у API-ролей. Cron/Vault/net не переносятся, production webhook и alias не меняются. Это учебная копия без фоновых отправок, а не второе работающее production-приложение.

## Файлы и доступ

`recovery-storage.cjs` использует отдельный защищённый `LEADLY_RECOVERY_SERVICE_ROLE_KEY` только для `umexhmyeheonfsktcyqi.supabase.co`. Запросы к другим origin и redirects запрещены. Файлы загружаются штатным Storage API в приватные buckets с исходными ограничениями. Перед повтором проверяются уже существующие пути/размеры/контрольные суммы; upsert выключен. После загрузки файлы повторно скачиваются и проверяются по SHA256. Строки storage.objects напрямую не вставляются.

На22.10 API чтения ключей через Management PAT вернул403. SQL-доступ подтверждён; это не даёт права извлекать ключи обходным путём. Для файлов владелец вводит server key новой цели через защищённые настройки среды. Для отдельного интерфейса нужен её anon/publishable key в обычной переменной `LEADLY_RECOVERY_PUBLISHABLE_KEY`. Серверный ключ в браузер не передаётся. Эти ключи не заменяют production bindings.
