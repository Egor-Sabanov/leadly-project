# LEADLY

AI-платформа для поиска возможностей заработка.

## Статус

**Foundation v0.3 — авторизация, профиль и первый Opportunity Engine.**

Реализованы Supabase Auth, профиль/предпочтения, лента возможностей из таблицы Supabase, сохранение предложений и эвристический Match Score / Money Score v1. Главная панель всё ещё частично использует демонстрационные метрики. Автоматический сбор внешних источников и полноценные AI-функции ещё не подключены.

## Принципы разработки

1. Сначала архитектура и контракты данных, затем интеграции.
2. UI не должен зависеть от конкретного поставщика данных.
3. Пользовательские данные не хардкодятся в production-слое.
4. Все AI-выводы в будущем должны иметь источник/уверенность там, где это возможно.
5. Auth и данные строятся с учётом RLS и server-side проверки.
6. Не добавляем функцию только ради «красивого демо» — она должна вести к действию или результату.

## Стек

- Next.js 16.4
- React 19.3
- TypeScript
- Tailwind-ready архитектура / собственные design tokens на первом этапе
- Lucide React
- Supabase PostgreSQL + Auth
- `@supabase/ssr` для cookie-based SSR auth

## Настройка Supabase (обязательно для авторизации)

1. Скопируй `.env.example` в `.env.local` в корне проекта.
2. В Supabase Dashboard открой **Project Settings → API** (в новом интерфейсе API Keys).
3. Заполни `NEXT_PUBLIC_SUPABASE_URL` адресом проекта и `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` публичным ключом `sb_publishable_...`. Если доступен только legacy `anon` key, можно задать его в `NEXT_PUBLIC_SUPABASE_ANON_KEY`.
4. Не помещай `service_role`/secret key в переменные `NEXT_PUBLIC_*` и не отправляй их в браузер.
5. После изменения `.env.local` останови сервер (`Ctrl+C`) и запусти `npm run dev` заново.

Без этих значений приложение покажет понятную ошибку при попытке авторизации вместо падения при загрузке модуля.

## Запуск

```bash

npm run dev
```

Открыть `http://localhost:3000`.

```bash
npm run lint
npm run build
```

На текущей среде зависимости npm не были скачаны из сети, поэтому финальная `lint/build` проверка должна быть выполнена после `npm install` в среде с доступом к npm registry.
