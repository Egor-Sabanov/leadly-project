# LEADLY

Русскоязычное рабочее пространство digital-специалиста: персональная лента, объяснимая оценка, отклики, проекты, клиенты и финансовый журнал. Тёмный монохромный адаптивный интерфейс, локальный шрифт Golos Text с кириллицей и увеличенный текст; анимации учитывают `prefers-reduced-motion`.

Новый визуальный вариант и галерея экранов: [DESIGN-REVIEW](docs/DESIGN-REVIEW.md). Направление — спокойный премиальный тёмный интерфейс; порядок текущей работы — технические сценарии приложения, бот, затем тарифы и оплата.

Публичное приложение: https://leadly-topaz-seven.vercel.app. На Vercel размещён проверенный снимок ветки `leadly-mvp-download`; Git-интеграция и автоматическое развёртывание `main` не подключались. Текущий результат и ограничения — в [TECHNICAL-RELEASE](docs/TECHNICAL-RELEASE.md), требования владельца — в [PRODUCT-REQUIREMENTS](docs/PRODUCT-REQUIREMENTS.md).

## Запуск

Нужен Node.js 24.x (проверено на Node 24.19.0). В корне проекта:

```bash
npm ci
npm run dev
```

Без внешних настроек доступны форма входа, информация о подключениях и демонстрация `/demo`. Примеры в демо вымышлены и не записываются в базу. Рабочие разделы используют Supabase и не подменяют реальные данные демонстрационными.

Для production: `npm run build`, затем `npm start`. После изменения `NEXT_PUBLIC_*` нужна новая сборка.

В этой облачной среде установлен Node 24 и обязателен HTTPS-прокси: запускай сервер как `NODE_USE_ENV_PROXY=1 npm run dev` или `NODE_USE_ENV_PROXY=1 npm start`. Без флага серверные запросы к Supabase здесь не проходят. На обычном компьютере без такого прокси флаг не требуется.

## Подключение базы

1. Сохрани резервную копию существующего проекта Supabase. Не используй reset базы.
2. Новая база: выполни SQL-файлы `supabase/migrations/0001...0006` в порядке номеров. Для существующей базы сначала сверь схему и триггеры, затем примени только недостающие обновления. Для проверенной базы этого проекта подготовлен атомарный bundle [DATABASE-UPDATE](docs/DATABASE-UPDATE.md), сохраняющий прежний регистрационный триггер. 0001 нельзя повторно накатывать вслепую: политики уже могут существовать.
3. Создай `.env.local` по `.env.example`. Заполни `NEXT_PUBLIC_SUPABASE_URL` и `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` из настроек своего проекта. Legacy `NEXT_PUBLIC_SUPABASE_ANON_KEY` также поддерживается. Service-role key никогда не должен попадать в `NEXT_PUBLIC_*`.
4. В Supabase Auth настрой Site URL и разрешённые Redirect URLs для `/auth/callback` и `/auth/callback?next=/auth/reset` на адресе своего развёртывания. Проверь email-шаблоны, подтверждение адреса, SMTP и восстановление пароля. В production используй HTTPS.
5. Перезапусти приложение. Зарегистрируй двух тестовых пользователей и проверь изоляцию данных по [инструкции запуска](docs/MVP-LAUNCH.md).

Миграция 0004 добавляет `skills_summary`, предварительный выбор плана, воспроизводимое создание профиля (сохраняя найденный прежний профильный триггер), атомарное сохранение профиля/предпочтений и статуса/истории, серверный контроль AI-лимитов. Старые данные и миграции не удаляются.

## Возможности

- Auth: регистрация, вход, выход, email callback, восстановление пароля, обновление cookie-сессии. OAuth Google/GitHub и подключаемые custom-провайдеры VK ID/Яндекс ID с PKCE и проверкой доступности. Живой вход требует настройки провайдеров в Supabase.
- Профиль: специализация, свободные навыки, каталог навыков и услуг, цель и валюта, предпочтения.
- Лента: только русскоязычные записи, поиск, типы, сохранённые, сортировка, оценки v14 с объяснениями, исключение истёкших предложений и сохранение оценок. Язык проверяется при импорте и повторно при чтении; неопределённые тексты скрываются.
- Карточка: оригинал, описание, оценка, заметки, статус и история.
- Мои проекты: четыре этапа, поиск, смена статуса с атомарной историей.
- Отклики: редактируемый шаблон без провайдера; опциональная настоящая AI-генерация через сервер. Выбор предложения из ленты переносится в редактор. Сохранение истории и копирование; автоматической отправки нет.
- Контакты: ручное добавление, поиск, статусы, удаление с подтверждением.
- Финансы: доходы/расходы, отдельный учёт валют, экспорт загруженного журнала. Показатели главной берутся из реальных записей.
- Аналитика: текущая воронка, отмеченные ответы и недельная активность.
- Источники: официальный hh.ru API, RSS/Atom, официальный Freelancehunt API, Telegram webhook для разрешённых публичных каналов. Секреты в UI не раскрываются.
- Аватарка для всех вошедших пользователей: выбор JPG/PNG/WebP до 5 МБ, кадрирование и масштаб, замена и удаление с подтверждением. Сжатие до 512×512, закрытое серверное хранилище и повторная проверка изображения на сервере.
- Мои задачи: дела с датой и клиентом, редактирование, выполнение и удаление; сохраняются в существующем follow_ups с RLS. Краткий список доступен на главной.
- Тарифы находятся **только в профиле**, отдельная вкладка `/profile/plans`: FREE / 990 / 2 490 / 4 990 ₽ в месяц. Платные планы — предварительный выбор; списания, подписки, лимиты платных прав и команда пока не активируются.

Технический этап и критерии запуска: [TECHNICAL-PLAN](docs/TECHNICAL-PLAN.md). Команда `npm run check:readiness` проверяет текущие подключения без изменения данных.

## Аватары и реальные задания

После защищённого добавления серверного ключа выполни `npm run setup:profile-storage` — команда создаёт или проверяет закрытое хранилище `leadly-profile-avatars`. В этой облачной базе оно уже создано. Настройка нужна один раз на сервер приложения, а не отдельно каждому пользователю. Браузер подготавливает выбранный кадр до отправки; API дополнительно проверяет тело до 2 МБ, разрешение до 16 млн пикселей и сохраняет только WebP 512×512. Миграция таблиц для новых аватаров и дел не нужна: используются `profiles.avatar_url` и `follow_ups`. Файлы нельзя открыть через публичный Storage URL; API проверяет сессию и работает только с собственным путём пользователя. При полном удалении аккаунта оператор удаляет и его объект аватара.

`npm run sources:sync -- --rss-only` импортирует официальные ленты FL.ru и Freelancehunt: только записи на русском, без копирования страниц и обхода доступа. Повторный импорт обновляет запись по канонической ссылке. В этой базе импортированы реальные заказы. У RSS часто нет подтверждения удалённого формата: такие задания остаются в ленте с отметкой «Формат не указан». До заполнения профиля отображается вся доступная русскоязычная подборка. После сохранения навыков и услуг включается режим «По моему профилю»; режим «Все задания» доступен рядом. Формат работы выбирается отдельно и сохраняется в этом браузере. Неуказанный формат не подменяется удалённой работой.

В task-проекте Vercel опубликован ежедневный защищённый `/api/cron/ingest` с `CRON_SECRET`; ручной вызов планировщика проверен. Постоянный планировщик облачного чата не используется. HH ранее отвечал 403; Kwork требует разрешённого доступа. Импорт Telegram требует согласованных каналов и доступа бота; личный Mini App работает отдельно от каналов. Google-вход и Gmail SMTP проверены владельцем; остальные OAuth-провайдеры требуют собственных настроек.

## Проверки

```bash
npm run lint
npm test
npm run build
# или всё вместе:
npm run check
```

`npm test` запускает 525 проверок: источники и скоринг, границы запросов, SQL и изоляция аккаунтов, авторизация, аватары/задачи, развёртывание и плановый импорт, Telegram/Mini App, согласие и очередь уведомлений, фильтрация и персональная подборка. SQL исполняется настоящим PostgreSQL/WASM (PGlite), но Supabase Auth в этом наборе моделируется. База одноразовая; настоящая база и отправка писем/сообщений этим набором не затрагиваются. Live и browser-проверки описаны отдельно в техническом отчёте.

Браузерные проверки (Chromium, desktop и mobile):

```bash
npx playwright install chromium
npm run test:ui
```

Если Chromium уже установлен, можно задать `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`. Браузерный набор поднимает отдельную сборку на порту 3100 с отключёнными интеграциями; проверяет демо-сценарии, адаптивность, регистрацию/восстановление без настроек, навигацию, расположение тарифов, доступность axe и отказы API. Он не заменяет проверку реального Supabase. Не запускай параллельно другую сборку в той же `.next`.
