## Подготовленные изменения

- Публичный GET /api/status: только общий статус и время. Проверяются Auth, свежесть/исход импорта и включённое расписание 10 минут. Внутренние сведения и ключи не возвращаются. Снимок кешируется на сервере 30 секунд; HTTP-ответ no-store.
- GET /api/operations/monitor-recipient: только вошедший пользователь из серверного списка операторов, только его подтверждённый Telegram chatId. Обычный аккаунт и чужой ID доступа не дают. Это разовая настройка оператора, не клиентский сценарий.
- Независимый GitHub Actions монитор: повторная проверка сбоя, сообщение о восстановлении, ограничение повторов, сохранение состояния и retry_after без сокращения паузы Telegram. Перед сообщением проверяется именно @leadly_work_bot.
- Зашифрованная копия схем public/auth/storage и файлов Storage. PostgreSQL snapshot согласован внутри БД; общей транзакции с файлами нет, несогласованный набор отклоняется. До шифрования выполняется восстановление в отдельную пустую локальную БД и сверка строк/файлов.
- Автоматические cron/Vault/net-схемы в восстановление не переносятся; реальная база не является допустимой целью restore. Архив ключей/настроек Vercel и реальное восстановление входа на другом Supabase-проекте — отдельные задачи.
