# Уведомления прямо в Telegram

Запрос владельца 21 октября: включать новые задания кнопкой в боте, без перехода в профиль. Проверка второго аккаунта выявила отсутствующую подписку; после её добровольного сохранения проверочное сообщение пришло. Следующая доработка убирает этот лишний переход.

## Поведение

Кнопка «🔔 Уведомления» открывает состояние подписки и выбор: после обновления ленты, раз в день или не присылать задания. Бот обновляет это же сообщение и подтверждает нажатие. Напоминания о делах сохраняют своё текущее состояние; «🔕 Тишина» по-прежнему выключает все автоматические сообщения. Начальное включение требует нажатия пользователя. Текст объясняет, что приходят новые подходящие задания после включения, с проверкой ленты каждые 10 минут.

Сервер проверяет секрет webhook, личный чат и автора нажатия. Кнопки привязаны к текущему аккаунту; чужие, пересланные и оставшиеся от прежней привязки не меняют настройки другого кабинета. Callback не содержит UUID пользователя. Изменение частоты выполняет одна закрытая SQL-функция с блокировкой строки, сохраняя параллельные изменения напоминаний.

## Проверки и публикация

`npm run check`: 580 проверок, lint и production build прошли. Новые проверки: 11 сценариев кнопок, 4 сценария webhook, 8 SQL-сценариев и 3 сценария регистрации callback. Дополнительно настоящий локальный PostgreSQL подтвердил конкурентное первое включение напоминаний из веба и заданий из бота: оба выбора сохранены. Тестовая база удалена, сервер остановлен; production не менялся.

Пока это проверенный исходный код, не опубликованная функция. Сначала владелец устанавливает [0014_telegram_bot_notifications.sql](../supabase/migrations/0014_telegram_bot_notifications.sql). Эта миграция добавляет только функцию, существующие подписки при установке не включает. Затем выполняются проверка установленной RPC без изменения реальных подписок, точный source snapshot и deployment. Включённый cron после публикации добавит callback_query в существующий webhook с сохранением pending updates; повторные импорты не перерегистрируют уже исправленный webhook.

После регистрации владелец обновляет меню бота через `https://t.me/leadly_work_bot?start=menu` и проверяет выбор прямо в чате. Установку SQL, runtime deployment и настоящее нажатие не считать завершёнными по результатам offline-тестов. При работающем cron не создавать проверочных opt-in на production: использовать локальные модели и реальные действия владельца в его аккаунте.
