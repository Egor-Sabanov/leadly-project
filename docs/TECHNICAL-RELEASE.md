## Доработано в приложении

- Регистрация без мгновенной сессии переводит на отдельный шаг подтверждения почты. Пароль очищается, существование аккаунта не раскрывается. Ссылка «Не пришло письмо?» доступна и после ошибки входа.
- Повторная отправка использует `auth.resend`, не повторную регистрацию. Есть блокировка двойного запроса и минута ожидания с восстановлением после перезагрузки и между вкладками. В хранилище браузера только время следующей попытки. Это удобство формы; защита сервера — ограничения Supabase, они не отключались.
- Ошибки регистрации, входа, подтверждения и смены пароля отображаются по разрешённым кодам на русском. Неизвестная ошибка не раскрывает email, URL, токены или внутренний ответ провайдера. Ответы на восстановление/повторное подтверждение нейтральны.
- Новый `/auth/confirm` принимает только signup/email/recovery и ограниченный формат hash. Страница не использует токен при открытии/предзагрузке: требуется отдельное нажатие. Адрес очищается, referrer отключён для раздела Auth, страницы закрыты от индексации. Переход после проверки фиксирован: приветствие либо восстановление пароля. Неподдерживаемые виды токенов и произвольные `next` не добавлены.
- Для нового формата ссылок не нужен PKCE verifier из браузера регистрации. Старый OAuth/PKCE callback сохранён. Новые ссылки появятся в настоящих письмах **после применения двух подготовленных шаблонов**; действующие шаблоны Supabase агент не менял.
- Готовы русские HTML-шаблоны `supabase/templates/confirm-signup.html` и `reset-password.html`. Это исходники без секретов и реальных токенов.
