## Доработано в приложении

- Регистрация без мгновенной сессии переводит на отдельный шаг подтверждения почты. Пароль очищается, существование аккаунта не раскрывается. Ссылка «Не пришло письмо?» доступна и после ошибки входа.
- Повторная отправка использует `auth.resend`, не повторную регистрацию. Есть блокировка двойного запроса и минута ожидания с восстановлением после перезагрузки и между вкладками. В хранилище браузера только время следующей попытки. Это удобство формы; защита сервера — ограничения Supabase, они не отключались.
- Ошибки регистрации, входа, подтверждения и смены пароля отображаются по разрешённым кодам на русском. Неизвестная ошибка не раскрывает email, URL, токены или внутренний ответ провайдера. Ответы на восстановление/повторное подтверждение нейтральны.
- Новый `/auth/confirm` принимает только signup/email/recovery и ограниченный формат hash. Страница не использует токен при открытии/предзагрузке: требуется отдельное нажатие. Адрес очищается, referrer отключён для раздела Auth, страницы закрыты от индексации. Переход после проверки фиксирован: приветствие либо восстановление пароля. Неподдерживаемые виды токенов и произвольные `next` не добавлены.
- Для нового формата ссылок не нужен PKCE verifier из браузера регистрации. Старый OAuth/PKCE callback сохранён. Новые ссылки появятся в настоящих письмах **после применения двух подготовленных шаблонов**; действующие шаблоны Supabase агент не менял.
- Готовы русские HTML-шаблоны `supabase/templates/confirm-signup.html` и `reset-password.html`. Это исходники без секретов и реальных токенов.

20 октября Admin API подтвердил поддержку custom OAuth providers в этом проекте, список пуст. Маршруты/иконки проверяют реальное включение и скрывают неподключённые способы. Для VK ID нужно проверить актуальные требования code/device_id/PKCE и выдачи email на реальном приложении. Произвольные endpoint, `email_verified=true`, ослабление state/nonce/PKCE или автоматическое объединение по неподтверждённой почте не допускаются. Нынешний подготовленный маршрут **не означает работающий вход VK/Яндекс**. Доступа к кабинетам владельца и секретов этих приложений нет, настоящий вход не проверен.

Для Яндекс подготовлен `/api/auth/yandex/userinfo`: сервер получает профиль только с фиксированного официального `login.yandex.ru/info`, преобразует стабильный id/email/имя в стандартный формат Supabase, не создаёт сессию и не сохраняет токен. Bearer принимается только из заголовка, запрос ограничен временем/размером, перенаправления и кеширование запрещены. Необязательные поля, телефон и другие адреса не возвращаются. `email_verified` остаётся false: наличие `default_email` не используется как доказательство подтверждения. После создания приложения владелец сохраняет ID/Secret в custom OAuth2 провайдере Supabase, затем выполняется настоящий сквозной прогон. PKCE поддерживается официальным code flow Яндекс; запросы с настоящим токеном ещё не выполнялись.

Официальная документация Яндекс получена: [code flow](https://yandex.ru/dev/id/doc/ru/codes/code-url), [userinfo](https://yandex.ru/dev/id/doc/ru/user-information). Наличие OAuth2 endpoints не доказывает полную совместимость custom provider. Документация VK ID из этой среды не открылась; требуется проверка в доступном кабинете, без выдуманных настроек. Исходники установленного SDK и публичный код Supabase Auth использованы для проверки поведения custom provider.
