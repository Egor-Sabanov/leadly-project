## Настройки Vercel, которые задаются владельцем один раз

| Переменная | Где нужна | Значение |
| --- | --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | Build и Runtime | HTTPS URL своего проекта без `/rest/v1` |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | Build и Runtime | Публичный publishable key этого же проекта |
| `SUPABASE_SERVICE_ROLE_KEY` | Только сервер | Серверный секрет того же Supabase для приватных аватаров и служебных операций |
| `LEADLY_SITE_URL` | Runtime | Точный стабильный HTTPS origin приложения, когда Vercel выдаст адрес |

Секрет Supabase вводится в защищённые **Project Settings → Environment Variables** Vercel. Его нельзя делать `NEXT_PUBLIC_*`. Прокси-привязка секрета в облачном чате не переносится автоматически на Vercel; нельзя загружать её placeholder как настоящий ключ. Обычным пользователям никакие ключи не нужны.

До получения стабильного адреса `LEADLY_SITE_URL` можно оставить незаданным: первый запуск использует адрес текущего запроса. После назначения домена необходимо задать точный HTTPS origin и выполнить повторное развёртывание. Не задавать localhost на Vercel: новая проверка остановит сборку. Для рабочих проверок использовать production domain, а не временный адрес другой preview-ветки. Тариф хостинга выбирает владелец с учётом условий сервиса и коммерческого использования.

## Проверка после развёртывания

```bash
npm run check:deployment -- https://АДРЕС-ПРИЛОЖЕНИЯ
```

Команда только читает публичные маршруты, не следует OAuth-переходу, не создаёт аккаунты и не отправляет письма. Она проверяет:

- открытие /auth и /privacy, заголовки и отсутствие общего кеширования авторизации;
- перенаправление гостя с / и /profile на вход того же сайта;
- HTTP 401 личных API без сессии;
- безопасное возвращение при ошибке callback и отказе провайдера;
- запрет произвольного провайдера и доставку статического файла Next.js;
- у включённого Google — точный Supabase, PKCE, verifier cookie и callback этого сайта.

Публичный прогон на постоянном адресе прошёл: `transportReady=true`. После сохранения Google владельцем повторная проверка дала 13/13 pass, в том числе `google_oauth=pass`. `realUserSignInVerified` у этой команды остаётся false: она не выполняет вход. Живой вход и действия с данными проверяются отдельным сценарием ниже. Первый настоящий Google-вход владелец подтвердил отдельно сообщением «работает». Письмо подтверждения регистрации на другой новый адрес пришло и ссылка сработала по проверке владельца. Владелец также подтвердил письмо восстановления, смену пароля и повторный вход. Полный Google-сценарий на телефоне ещё не подтверждён. После первоначально выключенного Custom SMTP владелец сообщил о сохранении Gmail-настроек для небольшого теста без собственного домена; доставка именно с новым отправителем ещё проверяется. Параметры и проверка описаны в AUTH-LAUNCH.md.

Для Vercel с Deployment Protection проверка может получить страницу входа Vercel вместо LEADLY. В таком случае нужно выбрать правильный production URL или предоставить поддерживаемый доступ к deployment, а не отключать TLS.

Семь личных страниц прошли автоматическую axe WCAG A/AA проверку; аватар проверен при ширине 320/390 px, настройки — без горизонтального переполнения при 390 px. Автоматическая проверка не заменяет ручную оценку доступности.
