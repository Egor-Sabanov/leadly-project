# Вход, аватары и cookies: технический запуск

## Что работает в приложении

Вход и восстановление по почте, серверный callback, PKCE при переходе к социальному провайдеру и защита личных страниц. После успешного входа показывается приветствие. Новый пользователь соцсети перед первым переходом в рабочее пространство подтверждает ознакомление с обработкой данных: сервер сохраняет актуальную версию и собственное время в метаданных именно вошедшего аккаунта. Подтверждение не объединяет аккаунты, не разрешает маркетинг и не меняет тариф.

Кнопки сервисов остаются иконками. Они становятся доступны только после подтверждения включённого провайдера в Supabase. Проверки редиректов и сценария подтверждения в тестах не являются настоящим входом в Google/VK/Яндекс.

Постоянный адрес текущего приложения: **https://leadly-topaz-seven.vercel.app**. Владелец сохранил Site URL и точные redirect URL в Supabase; отдельная проверка генерации recovery-ссылки для служебного аккаунта подтвердила `/auth/callback?next=/auth/reset` этого сайта без отправки письма. Google включён владельцем в Supabase: повторная проверка без кеша подтвердила external.google=true. На опубликованном сайте проверены PKCE, точный callback приложения и следующий переход Supabase к accounts.google.com с callback своего Supabase. Client ID/Secret, state и verifier в отчёты не выводились. После открытия публичного сайта владелец сообщил «работает», подтвердив первый реальный Google-вход. Это пользовательская проверка, а не автоматический вход агента; повторный вход/отказ/выход на телефоне и доставка писем ещё не подтверждены.

## Однократные настройки владельца для Google и GitHub

1. В кабинете выбранного провайдера создать OAuth-приложение для своего продукта. Для Google нужен Web Application и настроенная аудитория consent screen. Для GitHub — OAuth App. В тестовом режиме Google добавить нужные тестовые аккаунты.
2. Разрешённый callback **у провайдера** для текущего Supabase: `https://leezcyaqhozguvcehcpd.supabase.co/auth/v1/callback`.
3. Client ID и Client Secret сохранить в **Supabase → Authentication → Sign In / Providers → Google** или GitHub, затем включить провайдера. Секрет не помещать в `NEXT_PUBLIC_*`, репозиторий или чат. Серверный ключ Supabase не заменяет OAuth Client Secret.
4. В **Supabase → Authentication → URL Configuration** задать постоянный HTTPS Site URL и точные разрешённые callback приложения. Для локальной разработки: `http://localhost:3000/auth/callback` и `http://localhost:3000/auth/callback?next=/auth/reset`. Если используется `127.0.0.1`, добавить соответствующие два точных адреса отдельно. Для production использовать свой HTTPS origin с теми же путями. Не разрешать произвольные домены.
5. На сервере приложения задать `LEADLY_SITE_URL` ровно тем origin, который открывается в браузере, и перезапустить приложение. Публичные Supabase URL/ключ требуются также при сборке Next.js. Изменение `.env.local` на компьютере не меняет облачную среду и наоборот.
6. Запустить `NODE_USE_ENV_PROXY=1 npm run check:readiness` в управляемой облачной среде; на обычном сервере выполнить `npm run check:readiness`. Отчёт отдельно показывает доступность Google, GitHub, VK и Яндекс. Флаг включения означает конфигурацию, а не проверенный вход.
7. На опубликованном сайте проверить новый аккаунт: кнопка → настоящий экран провайдера → callback → ознакомление → бренд-приветствие → профиль. Затем отказ у провайдера, повторный вход, сохранение аватара, выход и вход на телефоне. Для существующего email-аккаунта проверить поведение именно его подтверждённых идентичностей в Supabase; не объединять аккаунты по неподтверждённому адресу.

Доступа к кабинету Google/GitHub и OAuth-секретов в этой среде нет. Эти настройки нельзя достоверно создать из одного серверного ключа Supabase. VK и Яндекс требуют отдельно проверенной совместимой custom OAuth/OIDC-конфигурации; подробности в DARK-RUSSIAN-AUTH.md.

## Если аватар не загружается

Фото добавляется в **Профиль → Добавить фото**: JPG/PNG/WebP до 5 МБ, выбор кадра и сохранение. Сохранённое фото появляется рядом с приветствием; нажатие на него ведёт к редактированию. У каждого аккаунта свой закрытый файл, публичного Storage URL нет.

Если API отвечает `503` с кодом `avatar_not_configured`, сервер приложения запущен без `SUPABASE_SERVICE_ROLE_KEY`. Это причина прежнего сообщения «Загрузка аватарок пока недоступна». Владелец один раз задаёт серверный ключ в защищённых серверных настройках и запускает `npm run setup:profile-storage`; затем перезапускает приложение. Ключ никогда не нужен конечным пользователям и не должен иметь префикс `NEXT_PUBLIC_`. Если ключ уже настроен, `npm run check:readiness` проверит закрытый bucket и его ограничения. Объект не делают публичным ради исправления ошибки.

В текущей облачной копии и публичном приложении Vercel серверное подключение и закрытое хранилище доступны; загрузка, замена, сохранность после перезагрузки и подтверждённое удаление проверены браузером на опубликованном сайте. Это не означает, что ключ задан в Windows-папке пользователя или на другом хостинге. При недоступности storage остальной профиль продолжает работать, а ошибка сохранения позволяет повторить действие.

## Cookies

Общее уведомление сообщает о необходимых cookies сессии и отсутствии рекламных/аналитических трекеров. Кнопка «Понятно» сохраняет только отметку прочтения в localStorage этого браузера; она не выдаёт разрешение на необязательный сбор. Отметка синхронизируется между вкладками. При запрете localStorage уведомление можно закрыть в текущем отображении; после перезагрузки оно появится снова.

Уведомление повторно открывается через «Настройки cookies» в настройках аккаунта и на странице конфиденциальности. Приложение резервирует место снизу, чтобы последние элементы страницы можно было прокрутить выше уведомления. При появлении необязательной аналитики сначала потребуется отдельный выбор с отказом и загрузка аналитики только после согласия.

До коммерческого запуска владелец должен заполнить реквизиты оператора, контакты и применимые юридические документы. Текущее уведомление описывает фактическую работу приложения и не объявляет юридическую подготовку завершённой.
