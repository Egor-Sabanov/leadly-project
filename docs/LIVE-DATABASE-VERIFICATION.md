# Живая проверка базы LEADLY

19 октября 2026 года, по Москве.

## Подтверждённый результат

SQL обновления применён владельцем в Supabase. Серверный API подтверждает новые RPC `leadly_save_profile`, `leadly_update_opportunity`, `leadly_reserve_ai`, поле `profiles.requested_plan` и таблицу `leadly_ai_requests`. Подготовленный SQL и локальные тесты описаны в DATABASE-UPDATE.md.

Через **настоящие Supabase Auth и REST API** выполнены 24 успешные проверки, используя два созданных для этого запуска временных аккаунта:

1. Создание двух подтверждённых тестовых аккаунтов и вход по паролю через Auth API. Admin API использовал `email_confirm=true`, без отправки почтовых сообщений.
2. Существующий регистрационный триггер создал отдельный профиль каждому аккаунту с прежним начальным `Europe/Chisinau`.
3. RPC сохранил профиль, навыки, цель, типы возможностей и выбранную временную зону каждого пользователя. После повторного входа данные сохранились.
4. Второй аккаунт не смог прочитать или изменить профиль первого. Интерес к AGENCY сохранился как поле профиля; списаний и активации платных прав нет.
5. Сохранились флаг избранного, заметка и статус задания. Повторная запись того же статуса не добавила лишнюю историю. У второго аккаунта состояние того же задания независимое.
6. Чужая воронка недоступна; подстановка чужого user_id при вставке отклонена. Анонимный вызов workflow RPC запрещён.
7. Создание, чтение, смена статуса и удаление собственного клиента работают; другой аккаунт клиента не видит.
8. Финансовая запись скрыта от другого аккаунта. Удалить чужую запись нельзя, удаление собственной после новой политики работает.
9. Черновик отклика сохраняется в истории; другой аккаунт не получает доступ к нему.
10. Пользовательский токен не может вызывать серверное резервирование AI. Серверный вызов разрешает 20 попыток и отклоняет 21-ю. OpenAI не вызывался, платной генерации не было.
11. Созданные тестом аккаунты и строки удалены; счётчики затронутых таблиц вернулись к исходным значениям. Существующие аккаунты и задания не изменялись.

Статусы/заметки проверялись в личных строках временных пользователей на существующем задании; глобальная запись задания не менялась. Удаление аккаунтов ограничивалось сохранёнными ID и проверкой уникального `leadly_validation_run` в метаданных. При ошибках промежуточных тестов также выполнена очистка с проверкой исходных счётчиков.

Приватный итог полного API-запуска сохранён вне GitHub: `/workspace/leadly-artifacts/live-db-validation-500d3342571044efbec7af2fb0dca972.json`. В нём нет паролей, JWT или ключей. Остальные диагностические отчёты также находятся только в `leadly-artifacts`. Временные пароли/токены передавались в памяти, не в аргументах команд и не в исходниках.

## Проверка через настоящий браузер

После разрешения пользователя продолжена проверка с действующей TLS-валидацией. Устранены две проблемы облачной среды: серверному Node 24 требуется `NODE_USE_ENV_PROXY=1`, а системный Chromium 154 аварийно завершался при скачивании Blob с HTTP-origin. Установлен совместимый с lockfile Chrome for Testing 156.0.8078.4 через Playwright; проверены HTTPS и воспроизведение скачивания.

В выделенном тестовом профиле доверие к официальному CA прокси ограничено DNS-именем `leezcyaqhozguvcehcpd.supabase.co`. Проверка сертификатов не отключалась. Первый запрос изменения общего NSS был отклонён автоматической проверкой разрешений; затем пользователь явно разрешил настройку доверия. Прежний отказ больше не является текущей блокировкой. Запись в NSS сама по себе не решила проблему: успешный браузерный прогон использует отдельное профильное хранилище сертификатов полного Chrome, а не Chrome Headless Shell.

Завершены **18 живых браузерных проверок**:

1. Вход по паролю устанавливает cookie-сессию, доступную серверным страницам.
2. Выбор направления видеомонтажа, сохранение имени/навыков и восстановление профиля после перезагрузки.
3. Предварительный выбор PRO+ сохраняется без оплаты.
4. Пустая лента объясняет фильтр удалённой работы и ведёт к изменению предпочтения. После его снятия появляются русскоязычные задания. В текущей базе 11 активных русскоязычных записей, удалённый формат у них не указан; это не подтверждение актуальности объявлений у источника.
5. Личная воронка загружает ранее сохранённое состояние.
6. Добавление контакта через форму сохраняется после обновления сервера.
7. Изменение статуса контакта переживает перезагрузку; удаление требует подтверждения.
8. Скачанный JSON финансов содержит собственную тестовую запись и точную сумму 2 222,22.
9. Создание и подтверждённое удаление собственной финансовой операции.
10. Карточка русскоязычного задания сохраняет избранное, статус, заметку и историю после перезагрузки.
11. Персональный шаблон отклика сохраняется в приватную историю и повторно открывается после перезагрузки. AI и отправка клиенту не вызывались.
12. Лента возможностей открывается с настоящей сессией без ошибки базы.
13. Аналитика открывается с настоящей сессией без ошибки базы.
14. Источники открываются с настоящей сессией без ошибки базы.
15. Автоматический axe-аудит пяти страниц с авторизацией (профиль, клиенты, финансы, отклик, источники) не выявил нарушений WCAG A/AA. Проверка ждёт окончания конечных анимаций; это не полный ручной аудит доступности.
16. Страница источников при ширине 390 px не имеет горизонтального переполнения.
17. Выход удаляет сессию, а приватная воронка снова требует входа.
18. Второй подтверждённый тестовый аккаунт проходит первоначальную настройку профиля через браузер, сохраняет видеонаправление и попадает в собственный кабинет.

Дополнительный API-запрос подтвердил, что рассчитанные в браузерном сценарии оценки сохранились и недоступны второму пользователю. После теста удалены только два помеченных аккаунта и их строки. Счётчики всех 12 контролируемых таблиц, включая кеш оценок, вернулись к исходным значениям. Ошибок очистки нет.

Находки исправлены в продукте: пустое состояние учитывает фильтр удалённой работы и предлагает переход в профиль; счётчик показывает размер подборки, а не всей базы; убрана неверная подсказка о недоступности почтового входа; редактор отклика получил доступное название. До изменений сохранены резервные копии файлов.

## Локальные проверки и границы результата

Повторно прошли lint, все **198 локальных тестов**, production build с TypeScript и **16 изолированных browser-проверок**. Изолированный набор проверяет демо/адаптивность/доступность и границы API, живой набор выше — настоящую Supabase-сессию и данные. Результаты не смешиваются.

Создание подтверждённых временных пользователей через Admin API позволило проверить регистрационный триггер и onboarding без отправки писем. Доставка подтверждений регистрации, вход нового обычного пользователя через письмо и восстановление пароля через SMTP **не проверены**. Google/VK/Яндекс OAuth, платная AI-генерация, платежи, свежий импорт источников, Mini App и пользовательский Telegram-бот также не объявляются работающими.

## Что остаётся сделать

- Разработка продукта: дальнейшие визуальные доработки, Telegram Mini App, полноценный пользовательский бот и уведомления; затем оплата, платные права и командные функции AGENCY.
- Настройки владельца: OAuth-приложения и включение провайдеров в Supabase, redirect URL и проверенный SMTP. Секреты вводить только через защищённые настройки.
- Telegram: выделенный бот из BotFather, токен, разрешённые каналы и доступ от их администраторов; публичный HTTPS-адрес для Mini App/webhook. Найденные публичные ссылки не дают права автоматического чтения.
- Источники: выяснить отказ `403 forbidden` официального hh.ru API, подключить разрешённые API/RSS и расписание. Kwork и другие биржи остаются каталогом, пока официальный доступ не подтверждён.
- Запуск: выбрать постоянный HTTPS-хостинг и проверить сервисы на нём. Текущий localhost работает только внутри облачной машины.

Пользователь установил плагин Supabase и разрешил автономную работу с базой. В текущем наборе нет callable SQL/MCP-методов, Management API token или PostgreSQL connection string. Выполненная работа использует уже авторизованный Auth/REST API; следующие DDL-изменения готовить и проверять самостоятельно, объединяя необходимые действия владельца в один bundle.

Инструкции установки и запуска облачной среды обновлены в черновике: прокси Node, совместимый Chrome, проверки и сохранность данных. Сохранение черновика не означает публикацию или проверку восстановления в новой задаче.
