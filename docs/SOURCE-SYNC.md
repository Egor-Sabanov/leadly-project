# Обновление русскоязычных возможностей

## Расписание для текущего хостинга

`vercel.json` задаёт один production cron: `/api/cron/ingest`, `0 6 * * *` (UTC). На Vercel Hobby он вызывается раз в сутки в течение часа: примерно 09:00–10:00 по Москве. Более частые cron на этом плане не поддерживаются. Подключение расписания подтверждается отдельно после deployment; наличие файла или секрета ещё не доказывает выполнение.

Источники по умолчанию — официальные RSS FL.ru и Freelancehunt. Обрабатывается до 100 записей каждой ленты, затем применяется русский языковой фильтр. Рубрики RSS сохраняются в category и используются вместе с названием/описанием при подборе профессии. Разные digital-профессии сохраняются. `LEADLY_RSS_FEEDS` может заменить список; только публичные HTTPS-адреса с проверкой перенаправлений, DNS и размера ответа. Kwork без разрешённого API/экспорта не подключается. Доступ к Telegram-каналам и включение API HH/Freelancehunt требуют отдельных настроек; расписание само по себе их не предоставляет.

## Защита и поведение

- `CRON_SECRET` — случайная серверная строка длиной минимум 16 символов в Production env. Vercel самостоятельно передаёт `Authorization: Bearer …`; секрет не добавляется в клиент, URL, Git или журналы. Проверка использует сравнение хешей за постоянное время. Гости получают 401.
- Тайм-аут функции — 300 секунд при включённом Fluid Compute. Рабочий дедлайн — 240 секунд; RSS-запрос ограничен 12 секундами, запрос к базе — 20 секундами. Ленты читаются последовательно.
- Временные сетевые ошибки, HTTP 408/429/5xx RSS и временный отказ записи пакета повторяются один раз с короткой задержкой. Отказ доступа, ошибка схемы, небезопасная ссылка или пустая нераспознанная лента требуют внимания оператора и не повторяются автоматически. Для API HH/Freelancehunt действуют их существующие адаптеры.
- Дубли внутри RSS удаляются по нормализованному `canonical_key` перед одной атомарной записью пакета. Повторный запуск обновляет существующие записи. Показатель `imported` включает новые и обновлённые возможности; он не означает число новых заказов. Пользовательские статусы, отклики, задачи и профили импорт не записывает.
- Сбой одного источника не отменяет успешные источники. Полный успех возвращает 200/completed, частичный — 502/partial, полный отказ — 502/failed. Ответы не кешируются. Vercel не повторяет неуспешный cron самостоятельно; после встроенной попытки нужен следующий запуск или действие оператора.

## Проверка оператором

Из привязанного task-проекта `leadly`, scope `egor-sabanov`, авторизованным официальным Vercel CLI:

```bash
vercel crons ls --project leadly --scope egor-sabanov --format json
vercel crons run /api/cron/ingest --project leadly --scope egor-sabanov
vercel logs --project leadly --scope egor-sabanov --environment production --query 'requestPath:/api/cron/ingest' --since 1h --json
```

CLI запускает уже опубликованную задачу; `crons run` не доказывает наступление очередного времени расписания. В журналах нужно найти пару `ingestion_started` / `ingestion_finished` с одним `runId`, исходами по источникам, временем и количеством записей. Затем проверить реальные строки в базе и доступность ленты авторизованному пользователю. Не извлекать секреты из Vercel и не печатать заголовки авторизации для ручного HTTP-запроса.

Для запуска из управляемой облачной среды с уже настроенным серверным доступом:

```bash
NODE_USE_ENV_PROXY=1 npm run sources:sync -- --rss-only
```

Команда использует тот же обработчик с отдельным временным секретом только в памяти процесса. Она действительно обновляет базу. Для автономной проверки без сети и базы: `npm run test:ingestion`. Полная проверка — lint, `npm test`, readiness и production build.

## Границы этапа

Схема и RLS базы не меняются. Итоги доступны в служебных логах Vercel; отдельного долговременного журнала запусков и распределённой блокировки пока нет. Параллельные повторы ограничиваются уникальным ключом и upsert; не запускать множество импортов одновременно. Отсутствие задания в коротком RSS не означает его закрытие: импорт не удаляет и не помечает такие записи закрытыми. Автоматическое подтверждение закрытия/устаревания, мониторинг пропуска расписания и история запусков остаются следующими улучшениями. Перед откликом пользователь проверяет условия в первоисточнике.

Официальные ограничения: https://vercel.com/docs/cron-jobs/usage-and-pricing , https://vercel.com/docs/cron-jobs/manage-cron-jobs , https://vercel.com/docs/cli/crons .
