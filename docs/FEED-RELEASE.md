# Лента заданий: исправление пользовательских сценариев

20 октября 2026. Цель — реальная русскоязычная работа для разных digital-специалистов, понятная подборка и действия с заданиями без настройки серверов самим пользователем.

## Поведение

- До заполнения профиля отображаются все доступные русскоязычные заказы, проекты и вакансии, без скрытого ограничения по remote_only. В ознакомлении можно сначала перейти к заданиям и оформить профиль позже.
- После сохранения специализации, навыков/услуг и типов работы включается «По моему профилю». Учитываются направления и выбранные типы; фриланс включает клиентские проекты. Рядом всегда доступны «Все задания». Незаполненный профиль не создаёт ложную пустую персональную ленту.
- Подтверждённая удалённая работа, неизвестный формат и офис различаются. Отсутствие метки удалёнки не объявляется офисом. Строгий формат выбирается явно. Прежнее remote_only сохраняется как предпочтение при ранжировании; пользовательские настройки массово не переписывались.
- Формат, поиск, направление, тип, сортировка и сохранённые живут в URL и браузере, отдельно по аккаунту/этапу оформления профиля. URL имеет приоритет; повреждённое или недоступное хранилище не ломает список. Есть сброс.
- В основном маршруте проверяется до 500 записей каталога вместо первых 100, поэтому более редкие профессии не теряются в текущей базе. Карточки выводятся по 20 с «Показать ещё», поиск и счётчики используют всю загруженную подборку. При росте каталога за этот ограниченный объём нужна серверная пагинация; не объявлять этот предел неограниченным поиском по всей будущей базе.
- В меню: «Главная», «Найти задания», «Мои проекты». Заголовок проектов и аналитика используют те же понятия.

## Источники и тексты

RSS FL.ru/Freelancehunt теперь обрабатывает до 100 публикаций источника вместо 40, сохраняет рубрики и использует их при определении профессии. Монтаж строительных конструкций больше не принимается за видеомонтаж только по слову «монтаж». Языковой фильтр, DNS/HTTPS/redirect проверки, ограничения размера, канонические ссылки и upsert сохранены. Чужие сохранения, статусы и задачи импорт не изменяет. Закрытие заказа не выдумывается по его исчезновению из короткой RSS.

Из основной ленты убраны обходная плашка «Показать все форматы», вводная панель и повторяющиеся пояснения. Системные инструкции про Supabase/SQL убраны с клиентских экранов. Незадействованные способы OAuth скрыты; маршрут каждого по-прежнему отказывает до настройки. Кнопка внешней генерации отклика показывается только по защищённой серверной проверке доступности; обычный редактируемый черновик работает. Убран неработающий переключатель уведомлений Telegram; сам Mini App и связь аккаунта сохранены. Пояснения неопределённого бюджета остаются в подробностях оценки. Условия оплаты/согласие/настоящие ошибки не маскируются как успешное действие.

## Фактические проверки

До исправления: 138 активных русскоязычных записей, подтверждённо удалённых 0; по 12 направлениям записи были, но ассистирование и обучение не попадали в первые 100. Read-only отчёт feed-coverage-before.json находится вне Git. В облаке расширенный импорт обновил 46 записей Freelancehunt; FL.ru не прошёл локальную проверку DNS (непубличный/неразрешившийся адрес). Защиту не ослабляли; после публикации обе площадки нужно проверить официальным Vercel cron-trigger. HH снова ответил 403; Kwork и согласованные Telegram-каналы автоматически не подключены.

310 unit/SQL проверок, lint и production build прошли. Добавлены 22 проверки профиля/фильтров/загрузки и 2 сценария фактического RSS-обработчика (больше 40 записей, сохранение категорий, отрицание удалёнки). 26 изолированных desktop/mobile сценариев прошли. Двенадцать дополнительных браузерных сценариев с настоящими Supabase Auth/DB подтвердили: 139 заданий для нового аккаунта с legacy remote_only=true, наличие реальных записей во всех 12 профессиях, раскрытие карточек, фильтры/сброс/возврат/reload, layout/axe WCAG A/AA на 320/390/1440, сохранение профиля через реальную форму и автоматическую подборку 21 задания видеомонтажёру, возврат ко всей ленте, понятное меню, редактируемый отклик и работу без localStorage. Количества — на момент проверки, а не обещание постоянного числа или актуальности каждого исторического объявления.

Временный проверочный аккаунт marker-защищён и удалён вместе со своими строками в finally; baseline profiles/user_preferences/opportunity_scores восстановлен. Чужие аккаунты не редактировались. Писем и сообщений тесты не отправляли. Ранний сбой сохранения профиля оказался TLS-доверием в headless shell: диагностически shell получил ERR_CERT_AUTHORITY_INVALID, полный Chromium в сохранённом профиле — ожидаемый 401 без ключа с проверенным TLS. Использован ранее настроенный полный Chromium, TLS не отключался. Отдельно исправлена тесная кнопка «Сохранённые» на 320 px; итоговый прогон прошёл после перезапуска своего тестового сервера на новой сборке.

Журналы/приватные скриншоты вне Git: feed-unit.log, feed-lint.log, feed-build.log, feed-browser-isolated.log, feed-live-results.json, feed-live-browser.log, feed-source-sync.log. Исходники резервировались в leadly-backups до изменений. Telegram-токен, SMTP, Google, RLS и пользовательская база не требуют повторной настройки для этого изменения.
