Не просить повторять запросы во время ограничения. Провайдер production уже установлен со слов владельца: Gmail, smtp.gmail.com. Не извлекать пароль production через API/Vercel/SQL; владелец вводит отдельные реквизиты через штатную форму. Новые платные услуги/домен без согласования не приобретать. Если точный лимит остаётся неизвестен, нужен только безопасный код последнего /recover из Auth-журнала владельца.

По [официальной документации Supabase](https://supabase.com/docs/guides/auth/auth-smtp), стандартный SMTP предназначен для ознакомления: адреса участников организации,2 письма/час, без гарантии доставки. Custom SMTP в recovery теперь сохранён владельцем; custom SMTP production включён и использует Gmail, что подтверждено владельцем. Ошибку email_address_not_authorized или конкретный исчерпанный лимит без ответа провайдера не приписывать этому запросу.

После настройки/окончания ограничения владелец сам запрашивает письмо, открывает его и задаёт пароль копии, затем сверяет профиль, сохранения, дела и фото. Только его подтверждение закрывает ручную проверку. Рабочий пароль этим не меняется. Новые OAuth/SMTP/домены и полный RTO не считать восстановленными автоматически.
