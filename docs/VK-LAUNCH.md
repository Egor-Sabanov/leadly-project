# VK ID: подключение LEADLY

Приложение владельца: Web, публичное, ID `54837022`. Владелец подтвердил скриншотом базовый домен `leadly-topaz-seven.vercel.app` и доверенный Redirect URL `https://leadly-topaz-seven.vercel.app/auth/vk/callback`. Одноклассники/Mail не подключаются; QR и переход в установленные приложения VK остаются настройками VK. Наличие этих настроек само по себе не доказывает успешный вход.

## Поток

1. Кнопка VK в LEADLY начинает штатный `custom:vk` OAuth Supabase с PKCE. Без серверной конфигурации и включённого провайдера кнопка скрыта.
2. Supabase отправляет браузер на `/api/auth/vk/authorize`. Маршрут принимает только ожидаемые client ID, callback Supabase, code flow и S256. Сохраняет state/challenge в зашифрованной HttpOnly Secure SameSite=Lax cookie на пять минут и направляет на фиксированный `https://id.vk.ru/authorize`.
3. VK возвращает code/device_id/state на `/auth/vk/callback`. Маршрут проверяет cookie и state, удаляет cookie, возвращает браузер только в callback Supabase с исходным state и короткоживущим зашифрованным контейнером code/device_id/challenge. Контейнеры разных назначений криптографически разделены.
4. Supabase проверяет свой state и обращается к `/api/auth/vk/token` с серверной аутентификацией и PKCE verifier. Маршрут проверяет отдельный bridge secret, срок контейнера, grant, callback и S256 verifier, затем делает POST на фиксированный `https://id.vk.ru/oauth2/auth`. Обратно возвращает только access_token/token_type/expires_in; ID/refresh tokens не нужны.
5. `/api/auth/vk/userinfo` переводит Bearer-запрос Supabase в POST на `https://id.vk.ru/oauth2/user_info` и возвращает только стабильный user_id, email, ограниченное имя. `email_verified=false`: наличие адреса не заменяет подтверждение письмом. Сессию создаёт Supabase. Первый вход может потребовать письмо, затем повторное нажатие VK; существующий экран подтверждения уже обрабатывает этот сценарий.

Все направления фиксированы, без произвольных URL, перенаправлений upstream, логирования кодов/токенов и кеширования. Ограничены размеры body/profile, срок ожидания и длины параметров. Ошибки содержат только безопасные постоянные коды. Вход без cookie/state, с подменённым/просроченным контейнером или неверным verifier не обменивает токен. Повторное использование настоящего кода дополнительно блокирует VK.

## Серверная конфигурация

- `LEADLY_VK_CLIENT_ID` — публичный ID приложения.
- `LEADLY_VK_BRIDGE_SECRET` — отдельные случайные 32 байта в hex, только сервер. Это **не** защищённый/сервисный ключ VK. То же значение записывается как client_secret только провайдеру `custom:vk` в Supabase; в браузере его нет.
- Production HTTPS `LEADLY_SITE_URL`, URL/ключи Supabase уже настроены.
- Шаблон без секрета: `supabase/providers/vk.json`. Пока `enabled=false`; включать после deployment и проверок. Рабочие Google, Яндекс, SMTP и Telegram не менять.

Первое подключение создаёт только новый провайдер и две Production-переменные выбранного проекта LEADLY. Существующий провайдер/настройки не перезаписывать вслепую. Секрет генерируется при установке, не запрашивается у владельца и не включается в Git, отчёты или артефакты. Cookie-контейнеры не являются сессией и никогда не принимаются как user ID.

## Проверки и оставшийся шаг

19 тестов включают state/cookie/PKCE, подмену параметров и контейнеров, Basic/body client authentication, срок, ограничение body, фиксированные API и отказ при отсутствии email. Общий набор — 348. UI включает закрытый отказ callback без конфигурации на desktop/mobile. Внешний настоящий вход требуется отдельно: наличие кнопки и корректный redirect ещё не являются успешной сессией.

Владелец сначала сообщил, что email в разделе «Доступы» выключен, затем подтвердил: «Готово — email включён и сохранён». Предварительное условие для настройки провайдера выполнено. Настоящие токены/письма агент не получает. Отдельный виджет One Tap на странице LEADLY ещё не установлен: текущий этап — защищённый вход через существующую компактную кнопку и страницу VK.

Официальные исходники, проверенные 20.10.2026: [VKCOM/vkid-web-sdk](https://github.com/VKCOM/vkid-web-sdk), `src/auth/auth.ts` (device_id/verifier/state, POST auth/user_info), `src/utils/url/url.ts`, `src/constants.ts` (id.vk.ru). Прямой доступ к VK из рабочей среды отклонён сетевым proxy; ограничение не обходилось. Проверка настоящего разрешения в VK проводится владельцем в его браузере после публикации.
