Загрузка сохраняется в закрытом хранилище по собственному пути аккаунта. Есть замена, отмена, подтверждение удаления, повтор после ошибки и текст результата. Ключи пользователей не требуются. Владелец один раз настраивает серверный ключ и хранилище на том сервере, где работает приложение.

## Проверка подключений

```bash
npm run check:readiness
```

В облачной среде перед командой нужен `NODE_USE_ENV_PROXY=1`. Команда выполняется из рабочей копии с полной установкой `npm ci`, включая TypeScript-инструменты диагностики. Команда только читает настройки и метаданные, не создаёт пользователей и не изменяет базу. Она проверяет Auth, служебную русскоязычную выборку, отсутствие анонимной выдачи профилей и конфигурацию закрытого хранилища. Имена, почта, изображения и ключи в отчёт не выводятся. Работу с двумя настоящими сессиями проверяют отдельные живые сценарии.

`coreReady` означает, что эти базовые подключения отвечают без обнаруженной ошибки. Это не оценка готовности всего продукта. `commercialLaunchReady` пока false: платежи, операторские документы и весь процесс публичного запуска не завершены. Наличие переменной или токена не считается успешным OAuth-входом, Telegram-доставкой или работающим расписанием.

## Порядок дальнейшей технической работы

1. **Постоянная среда приложения и аккаунты.** Выбрать сервер/домен, разместить серверные настройки, проверить HTTPS, регистрацию и подтверждение email, восстановление, выход и повторный вход на телефоне. Добавить Google и выбранные соцсети в Supabase с точными callback URL. Проверить аватары двух новых аккаунтов на опубликованном приложении. Результат: новый пользователь самостоятельно проходит полный путь без помощи разработчика.
2. **Регулярная лента заказов.** Ежедневный защищённый cron опубликован на Vercel Hobby. Ручной вызов через официальный планировщик успешно обновил 73 записи FL.ru/Freelancehunt, 7 пропущены; русский фильтр, оригинальные ссылки, тип проекта и осторожная оценка бюджета сохранены. Временные ошибки RSS/записи повторяются один раз, исходы записываются в служебные логи. Новому тестовому аккаунту доступны 138 русскоязычных возможностей; его временные данные удалены. Первый запуск по наступившему времени, долговременная история, мониторинг пропущенных запусков и подтверждение закрытия/устаревания ещё предстоят. На Hobby только раз в сутки: для более частой ленты нужно отдельное решение. Kwork и другие площадки — только разрешённый API/экспорт; HH ранее отвечал 403, сбор заданий Telegram требует согласованных каналов. Инструкция: [SOURCE-SYNC](SOURCE-SYNC.md).
3. **Telegram Mini App и бот.** Мини-приложение использует существующие профиль, возможности, отклики, задачи и воронку. Сервер проверяет подпись и срок initData; связка Telegram с существующим аккаунтом требует подтверждения владельца аккаунта. Реализованы личные команды бота, открытие Mini App, подключение и отключение способа входа. Автоматические уведомления пока не реализованы. Для входящих заданий нужны согласованные каналы с доступом бота. Первый настоящий вход и открытие своего кабинета владелец подтвердил 20 октября 2026. Повторный вход, работа всех разделов и отзыв связи на настоящем устройстве ещё проверяются отдельно; уведомления — после реализации. Подготовка, настройки и границы проверок: [TELEGRAM-LAUNCH](TELEGRAM-LAUNCH.md). Произвольные каналы не читаются скрыто.
4. **Реальные тарифы.** Выбрать платёжного провайдера, реализовать проверку webhook, идемпотентность, выдачу и отзыв прав, продления, отмену и возвраты. До этого не активировать платные права за один запрос из браузера и не списывать деньги за неготовые функции. Цены остаются FREE / 990 / 2490 / 4990 ₽ в месяц.
5. **Проверяемый публичный запуск.** Заполнить реквизиты оператора и контакт для запросов, проверить документы и хранение данных, восстановление резервной копии, журналы ошибок без секретов, лимиты ресурсов, доступность и восстановление после отказа. Провести сквозной прогон на отдельных аккаунтах и затем небольшую закрытую проверку с пользователями.

## Что предоставляется владельцем один раз

- Постоянный адрес/хостинг и защищённые настройки сервера. Локальные настройки компьютера не передаются автоматически из облачного чата.
- Данные OAuth-приложений — в защищённых настройках провайдеров/Supabase.
- Бот и доступ к согласованным Telegram-каналам — через защищённые настройки.
- Разрешение/учётные данные интеграций площадок, если открытого RSS недостаточно.
- Платёжный кабинет и данные оператора перед приёмом оплат.

Секреты не отправляются в чат и не включаются в исходники или архив. Работающие модули и пользовательские данные сохраняются; новые изменения проверяются до публикации.
