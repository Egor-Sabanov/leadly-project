# LEADLY: переход от дизайна к техническому запуску

## Уже реализовано

Русская адаптивная оболочка, регистрация/вход по почте, настройка профиля, объяснимая оценка русскоязычных возможностей, сохранения и статусы, отклики, клиенты, финансовый журнал и личные задачи. Новые пользователи получают собственный профиль через существующий триггер. Тарифы находятся только в профиле; их выбор сохраняет интерес, не оформляет покупку.

Аватар доступен любому вошедшему пользователю независимо от тарифа. Выбор файла до 5 МБ и 16 мегапикселей, кадрирование, масштаб и положение, подготовка изображения 512×512 в браузере и повторная серверная проверка. Загрузка сохраняется в закрытом хранилище по собственному пути аккаунта. Есть замена, отмена, подтверждение удаления, повтор после ошибки и текст результата. Ключи пользователей не требуются. Владелец один раз настраивает серверный ключ и хранилище на том сервере, где работает приложение.

## Проверка подключений

```bash
npm run check:readiness
```

В облачной среде перед командой нужен `NODE_USE_ENV_PROXY=1`. Команда выполняется из рабочей копии с полной установкой `npm ci`, включая TypeScript-инструменты диагностики. Команда только читает настройки и метаданные, не создаёт пользователей и не изменяет базу. Она проверяет Auth, служебную русскоязычную выборку, отсутствие анонимной выдачи профилей и конфигурацию закрытого хранилища. Имена, почта, изображения и ключи в отчёт не выводятся. Работу с двумя настоящими сессиями проверяют отдельные живые сценарии.

`coreReady` означает, что эти базовые подключения отвечают без обнаруженной ошибки. Это не оценка готовности всего продукта. `commercialLaunchReady` пока false: платежи, операторские документы и весь процесс публичного запуска не завершены. Наличие переменной или токена не считается успешным OAuth-входом, Telegram-доставкой или работающим расписанием.

## Порядок дальнейшей технической работы

1. **Постоянная среда приложения и аккаунты.** Выбрать сервер/домен, разместить серверные настройки, проверить HTTPS, регистрацию и подтверждение email, восстановление, выход и повторный вход на телефоне. Добавить Google и выбранные соцсети в Supabase с точными callback URL. Проверить аватары двух новых аккаунтов на опубликованном приложении. Результат: новый пользователь самостоятельно проходит полный путь без помощи разработчика.
2. **Регулярная лента заказов.** Ежедневный защищённый cron опубликован на Vercel Hobby. Ручной вызов через официальный планировщик успешно обновил 73 записи FL.ru/Freelancehunt, 7 пропущены; русский фильтр, оригинальные ссылки, тип проекта и осторожная оценка бюджета сохранены. Временные ошибки RSS/записи повторяются один раз, исходы записываются в служебные логи. Новому тестовому аккаунту доступны 138 русскоязычных возможностей; его временные данные удалены. Первый запуск по наступившему времени, долговременная история, мониторинг пропущенных запусков и подтверждение закрытия/устаревания ещё предстоят. На Hobby только раз в сутки: для более частой ленты нужно отдельное решение. Kwork и другие площадки — только разрешённый API/экспорт; HH ранее отвечал 403, доступ Telegram пока не настроен. Инструкция: [SOURCE-SYNC](SOURCE-SYNC.md).
3. **Telegram Mini App и бот.** Мини-приложение использует существующие профиль, возможности, отклики, задачи и воронку. Сервер проверяет подпись и срок initData; связка Telegram с существующим аккаунтом требует подтверждения владельца аккаунта. Бот открывает Mini App, принимает разрешённые действия пользователя и доставляет уведомления. Для входящих заданий нужны согласованные каналы с доступом бота. Результат: проверенный вход, переход к заказу и уведомление на настоящем телефоне. Произвольные каналы не читаются скрыто.
4. **Реальные тарифы.** Выбрать платёжного провайдера, реализовать проверку webhook, идемпотентность, выдачу и отзыв прав, продления, отмену и возвраты. До этого не активировать платные права за один запрос из браузера и не списывать деньги за неготовые функции. Цены остаются FREE / 990 / 2490 / 4990 ₽ в месяц.
5. **Проверяемый публичный запуск.** Заполнить реквизиты оператора и контакт для запросов, проверить документы и хранение данных, восстановление резервной копии, журналы ошибок без секретов, лимиты ресурсов, доступность и восстановление после отказа. Провести сквозной прогон на отдельных аккаунтах и затем небольшую закрытую проверку с пользователями.

## Что предоставляется владельцем один раз

- Постоянный адрес/хостинг и защищённые настройки сервера. Локальные настройки компьютера не передаются автоматически из облачного чата.
- Данные OAuth-приложений — в защищённых настройках провайдеров/Supabase.
- Бот и доступ к согласованным Telegram-каналам — через защищённые настройки.
- Разрешение/учётные данные интеграций площадок, если открытого RSS недостаточно.
- Платёжный кабинет и данные оператора перед приёмом оплат.

Секреты не отправляются в чат и не включаются в исходники или архив. Работающие модули и пользовательские данные сохраняются; новые изменения проверяются до публикации.


## Продолжение после финальных штрихов

Добавлены оформление системных списков и прокрутки, аватар непосредственно рядом с приветствием и общее уведомление о необходимых cookies. Технический этап начат: новые пользователи соцсетей подтверждают ознакомление с данными до открытия личных страниц; сохранение идёт через защищённый серверный API в собственный аккаунт. Диагностика проверяет доступность всех четырёх способов входа отдельно. Конфигурация Google/GitHub и отличие callback провайдера от callback приложения описаны в [AUTH-LAUNCH](AUTH-LAUNCH.md).

Следующий внешний результат — настоящий вход через включённый OAuth-провайдер на постоянном HTTPS-адресе. Нужны OAuth-приложение владельца и его секреты в Supabase. Метаданные временного проверочного аккаунта используются только для проверки интерфейса ознакомления; они не доказывают реальный вход у провайдера. Telegram Mini App, бот, расписание и платежи остаются обязательными последующими этапами.
