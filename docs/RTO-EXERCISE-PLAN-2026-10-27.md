# Следующее учение полного восстановления

Состояние на27 октября2026: данные из нового скачанного архива реально восстановлены локально за3,318с (68 таблиц/2 файла), но полного RTO этот замер не даёт. Для hosted-учения требуется новая пустая цель. Текущая umexhmyeheonfsktcyqi содержит8 аккаунтов/2 файла/33 public objects и сохраняется.

## Цель и время

Записать UTC-время объявления начала учения, начала/готовности инфраструктуры, получения доступа, SQL, файлов, deployment, внешней конфигурации, первого обычного входа владельца и завершения пользовательских проверок. Считать полный интервал до принятого сервиса, включая ручные шаги; отдельно перечислить заранее подготовленные компоненты. Не выдавать время COMMIT или локального pg_restore за полное RTO.

## Ресурсы перед запуском

1. Владелец указывает существующий отдельный пустой Free-проект либо создаётся новый Free-проект в Европе. Ранее подтверждённый Supabase лимит —2 активных Free-проекта владельца. Через текущий project-scoped PAT полный список проектов403; наличие свободного слота ещё нужно установить.
2. Если слот занят, конкретный вариант — отдельно согласовать временную паузу только leadly-recovery (umexhmyeheonfsktcyqi) для создания нового Free-проекта. Это временно остановит закрытую копию, сохранив её данные. Production leezcyaqhozguvcehcpd сохраняется. Пауза/удаление/платные ресурсы до отдельного решения владельца не выполняются.
3. Доступ новой цели передаётся защищёнными полями, только для её Project Ref и нужных операций. Рабочие bindings старой recovery не заменяются ради удобства. Значения не передаются в чат. Сначала проверить штатные read-only операции; отказ scope не обходить через SQL/ключи другой платформы.
4. Новый закрытый Vercel Preview использует проверенный runtime7a80cdb или более поздний проверенный release; server key новой цели только Preview, Authentication ALL. Старый main приложения не разворачивать.
5. Для проверки бота нужен отдельный тестовый бот и согласованный маршрут к закрытому backend. Рабочий webhook @leadly_work_bot сохраняется. Ограничения Deployment Protection решаются до этого этапа; защиту всей копии ради webhook не снимать. Авторассылки и импорт выключены до отдельного согласованного теста.
6. Подготовить конфигурацию SMTP587/STARTTLS, Site URL/callbacks, разрешённые OAuth redirect URLs и настройки тестовых доменов. Использовать защищённое хранилище владельца/штатные API и консоли. Наличие SQL-архива не доказывает восстановление этих настроек.

## Исполнение после готовности ресурсов

- Зафиксировать точный архив, commit, SHA256 и возраст snapshot.
- Проверить live-пустоту, managed-схему/constraints/roles/triggers и совместимость PostgreSQL. Любые данные или несовместимость останавливают перенос.
- Подготовить отдельный явно привязанный к новому Ref исполнитель: транзакция, проверка hashes/counts до и после COMMIT, исключение старых sessions/refresh/one-time tokens, cron/Vault/net, leases и очередей уведомлений. Guard существующей занятой цели сохраняется.
- Восстановить собственные SQL/данные и приватные файлы без перезаписи; сверить SHA256 и RLS/изоляцию своими очищаемыми fixtures.
- Опубликовать закрытую копию на новой конфигурации. Проверить гостевые ограничения, Auth/Storage, личные данные и отсутствие запущенных сообщений.
- Участник сам выполняет обычный вход/выход/повторный вход, восстановление через почту и согласованные OAuth-сценарии, сверяет архивные данные. Агент не создаёт административную сессию владельца и не запрашивает его пароль/код.
- Проверить тестовый бот/Mini App и остальные внешние функции после согласования маршрута/доступов. Сообщения инструментами не отправлять без явного разрешения; владелец может сам вызвать команды тестового бота.
- Зафиксировать конец учения только после принятых сценариев. Вывести отдельные времена инфраструктуры/SQL/Storage/config/owner-flow и фактическую потерю данных. Все исключения остаются явно перечисленными.

## Завершение и возврат

Рабочие aliases, производственный Site URL и webhook не переключаются этим учением. Сохранить старую recovery-копию; судьба новой тестовой цели и возврат временно приостановленного проекта согласуются до расходования Free-слотов. Удалить только свои fixtures и временные plaintext/DB. Полное RTO пока не измерено, новые проекты не создавались и пауза не выполнялась.
