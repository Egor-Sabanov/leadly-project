## Обязательные шаги владельца

1. **Supabase.** Перед SQL — резервная копия и сверка текущей схемы/триггеров. В существующую базу с 0001–0003 применить только 0004. В новую базу применить все четыре миграции по порядку. Проверить grants, RLS и отсутствие дублирующего auth→profile триггера. Миграция распознаёт существующие профильные триггеры по телу функции; нестандартный динамический триггер нужно проверить вручную.
2. **Настройки.** Указать URL и публичный ключ в `.env.local` или настройках среды. Ни в чат, ни в Git не передавать service-role/API/cron секреты.
3. **Auth.** Задать `LEADLY_SITE_URL` точным HTTPS origin приложения; настроить Site URL, callback/reset redirect allowlist, email-подтверждение, SMTP, провайдерские rate limits. Выполнить регистрацию, вход, выход, восстановление и обновление сессии на выбранном адресе.
4. **Сквозной сценарий.** Пользователь A заполняет профиль, добавляет навыки, открывает ленту, сохраняет предложение, меняет статус, добавляет заметку, готовит и сохраняет черновик. После перезагрузки проверить сохранность. Пользователь B не должен видеть личные записи A. Отдельно проверить контакты, финансы и удаление записей.
5. **Развёртывание.** Настроить HTTPS, окружение, резервные копии базы и процесс перезапуска. После `NEXT_PUBLIC_*` выполнить build заново. Пройти сценарий на опубликованном адресе, не только в локальном окружении.

## RSS / Freelancehunt

- `SUPABASE_SERVICE_ROLE_KEY` — только серверный ключ.
- `CRON_SECRET` — длинный случайный секрет, используемый локальной проверкой bearer-заголовка; в облаке ему нужен прямой runtime binding, не только прокси-подстановка для удалённого домена.
- `LEADLY_RSS_FEEDS` — только выбранные владельцем разрешённые публичные HTTPS feeds. Проверь условия, атрибуцию и частоту.
- `FREELANCEHUNT_API_TOKEN` — необязательный токен официального API `api.freelancehunt.com`.
- Доверенный scheduler вызывает GET `/api/cron/ingest` с `Authorization: Bearer $CRON_SECRET`. Заголовок формируется из переменной; не вставляй реальный секрет в историю shell или URL.
- Проверь HTTP-ответ **и** `ok/results/imported/skipped/error`; HTTP 200 сам по себе не означает успешный импорт. SQL-ошибки RSS больше не превращаются молча в «всё хорошо, 0 импортировано».
- Ленты ограничены по числу, размеру, времени и редиректам. Проверяются HTTPS, публичные IP и DNS. Для production дополнительно ограничь исходящие домены: DNS-проверки приложения не полностью защищают от rebinding. Не открывай сеть на `*`.
- RSS-признак удалённой работы определяется по известному источнику/тексту и остаётся выводом, а не проверенным условием работодателя. Telegram не делает такой вывод: без доказательств удалённость не подтверждается.
- Расписание cron и первый live импорт в этом облачном экземпляре не выполнялись: нет настроек внешних сервисов.

## Telegram

Endpoint: POST `/api/telegram/webhook`. Он принимает `channel_post`, только если:

- совпадает `X-Telegram-Bot-Api-Secret-Token` с `TELEGRAM_WEBHOOK_SECRET`;
- `chat.id` явно включён в `TELEGRAM_ALLOWED_CHAT_IDS` (список через запятую);
- канал публичный и имеет username;
- `TELEGRAM_OPPORTUNITY_TYPE` явно задан как `project`, `job` или `client`.

Владелец должен создать бота, предоставить ему необходимый доступ к разрешённому каналу и через официальный Bot API `setWebhook` зарегистрировать HTTPS URL с `secret_token` и `allowed_updates: ["channel_post"]`. Токен бота не нужен приложению для приёма публикаций и не должен попадать в логи/чат. Приватные сообщения, пересылки и чужие каналы не импортируются. Публичные ссылки сохраняются как доказательство происхождения. Повторная доставка обновляет запись по canonical key.

Это входящий коннектор; уведомления пользователю, Telegram Mini App и массовая отправка не реализованы. Предпочтение Telegram в профиле не включает доставку само по себе.

## AI

- Шаблон отклика работает без внешнего сервиса.
- Настроить серверный `LEADLY_AI_API_KEY` для `api.openai.com`, при необходимости `LEADLY_AI_MODEL` (по умолчанию `gpt-4.1-mini`), URL Supabase и service-role key.
- Применить 0004: квота резервируется сервером в отдельной закрытой таблице. Лимит — 20 попыток за скользящие 24 часа на пользователя; неуспешная попытка тоже расходует квоту. Клиент не может сбросить счётчик.
- POST `/api/outreach` требует аккаунт, совпадающий Origin, валидный ID, ограниченное тело и активное предложение. Данные предложения запрашиваются через RLS, а не принимаются произвольным текстом из браузера.
- Только после явного нажатия AI-кнопки выбранные данные передаются OpenAI. `store:false`, ограничение вывода и тайм-аут. Токены usage записываются на сервере. Отклик остаётся черновиком: проверить факты и отправить вручную.
- До публичного запуска установить отдельный бюджет/лимиты провайдера, мониторинг ошибок, политику хранения и условия обработки данных. Живой вызов AI здесь не выполнялся.

## Тарифы

FREE — 0 ₽, PRO — 990 ₽/мес., PRO+ — 2 490 ₽/мес., AGENCY — 4 990 ₽/мес. План AGENCY рассчитан как стартовая гипотеза для небольшой команды до 5 человек: около 998 ₽ на участника. Это ценовая гипотеза, не подтверждённый исследованием оптимум рынка.

Планы находятся только в `/profile#plans`. Выбор платного плана сохраняет `requested_plan`, не создаёт подписку, не меняет права доступа и не списывает деньги. Платные/командные возможности явно отмечены планируемыми. Для продаж нужны выбранный платёжный провайдер, проверяемый webhook оплаты, серверные права/лимиты, отмена/возвраты и применимые документы оператора. Командная RLS-модель и website audit — отдельная работа после подключения и проверки базового MVP.

## Границы проверок

- `npm run check`: lint, текущие RSS/scoring/MVP/SQL-тесты, полный Next.js build с TypeScript.
- SQL-тесты — PostgreSQL/WASM с моделируемой `auth.uid`, свежая база и два пользователя. Это проверка SQL и RLS, а не всего работающего Supabase Auth.
- `npm run test:ui`: Chromium, desktop/mobile; демо, навигация, восстановление без конфигурации, размещение тарифов, границы API и axe A/AA. Интеграции в тестовом сервере намеренно отключены; реальные ключи не используются.
- Лимиты интерфейса: лента 100 активных записей, воронка/контакты 500, финансы/аналитика 1 000, неделя активности до 5 000 событий. Это MVP, не полный архив. Финансовый экспорт включает загруженные записи; валюты не смешиваются. Большие аккаунты потребуют пагинации и серверных агрегатов.
- Скриншоты/логи текущей проверки сохраняются в `/workspace/leadly-artifacts`. Браузерные результаты — `test-results/browser-results.json` (ignored).
- Нет утверждения о production deploy, работающих внешних источниках, платежах или коммерческой готовности до выполнения обязательных внешних шагов.
